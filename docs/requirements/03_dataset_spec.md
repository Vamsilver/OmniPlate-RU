# 03. Спецификация датасета

Датасет является **обязательным и отдельно оцениваемым результатом работы**, имеющим максимальный вес в итоговой оценке олимпиады.

---

## 1. Количественный состав выборки

Датасет строго делится на две части: **реальные** данные и **синтетические** данные.

| Категория | Группа знака | Минимальное кол-во изображений | Минимальное кол-во уникальных ГРЗ | Источники / Характер данных |
|---|---|---|---|---|
| **Реальные** | `type1a` (квадратные 2-строчные) | **$\ge 150$** | **$\ge 50$** | Собственные фото/видео, свободные датасеты, открытые фотобанки с CC BY |
| **Реальные** | `type1b` (жёлтые такси/автобусы) | **$\ge 300$** | **$\ge 100$** | Городской транспорт, таксопарки, свободные видеозаписи |
| **Реальные** | `other` (негативные примеры) | **$\ge 50$** | — | Мотоциклы, прицепы, спецтехника, иностранные, витрины |
| **Синтетика** | `type1`, `type1a`, `type1b` | **$\ge 5000$** | **$\ge 5000$** | Скрипт-генератор участника с фиксированным `seed` |

> [!IMPORTANT]
> **Требование к генератору синтетики**:
> Вместе с синтетическими изображениями обязательно сдаётся скрипт-генератор (`dataset/generator/`) с фиксируемым random seed и списком зависимостей (`requirements.txt`), позволяющий на 100% воспроизвести весь сгенерированный набор.

---

## 2. Структура файлового дерева датасета

Датасет должен иметь строго регламентированную файловую структуру:

```text
dataset/
├── images/
│   ├── real/                   # Реальные фотографии (.jpg, .png)
│   └── synthetic/              # Синтетические изображения (.jpg, .png)
├── labels/                     # Текстовые файлы разметки (по 1 файлу на изображение)
├── meta.csv                    # Единый реестр метаданных (разделитель ;)
├── generator/                  # Исходный код скрипта генерации
│   ├── generate_synthetic.py
│   └── requirements.txt
├── README.md                   # Датащит: описание источников, лицензий, статистики
└── LICENSE                     # Файл лицензии Creative Commons Attribution 4.0 (CC BY 4.0)
```

---

## 3. Схема метаданных (`meta.csv`)

Файл `meta.csv` содержит одну строку на каждый знак на изображении (если на изображении 2 знака — будет 2 строки с одинаковым путем к `image`).
- **Разделитель**: `;`
- **Кодировка**: `UTF-8`

| Поле | Формат | Пример значения | Описание |
|---|---|---|---|
| `image` | `str` (относительный путь) | `images/real/img_0042.jpg` | Относительный путь от корня `dataset/` |
| `plate_num` | `str` (маска) | `A123BC716` | Номерной знак (латиница верхнего регистра, `#` для нечитаемых) |
| `plate_type` | `enum` | `type1a` | Одно из: `type1`, `type1a`, `type1b`, `other` |
| `bbox` | `int,int,int,int` | `120,340,180,95` | Bounding box в формате `x,y,w,h` в абсолютных пикселях |
| `quad` | `int x 8` | `120,345,295,340,300,435,125,440` | Четыре угла знака `x1,y1,x2,y2,x3,y3,x4,y4` по часовой стрелке от верхнего левого угла |
| `is_vehicle` | `int` (`0` или `1`) | `1` | `1` — знак на реальном ТС; `0` — щит, реклама, экран, наклейка |
| `is_synthetic` | `int` (`0` или `1`) | `0` | `1` — сгенерировано скриптом; `0` — реальное фото |
| `source` | `str` | `own_photo` или URL | Источник кадра (`own_photo`, Kaggle, Roboflow URL, etc.) |
| `license` | `str` | `CC-BY-4.0` | Лицензия конкретного источника |
| `conditions` | `str` (через запятую) | `day,angle,glare` | Теги условий съемки: `day`, `night`, `rain`, `snow`, `dirt`, `glare`, `motion_blur`, `angle` |

---

## 4. Формат меток в папке `labels/`

Для каждого файла в `images/` создается соответствующий `.txt` в папке `labels/` (например, `labels/real/img_0042.txt` или плоская структура `labels/img_0042.txt`):
Каждая строка описывает один объект:
`class_id x_center y_center width height p1_x p1_y p2_x p2_y p3_x p3_y p4_x p4_y plate_num`
(Нормализованные или абсолютные координаты согласовываются со скриптом `validate_dataset.py`).

---

## 5. Валидация перед сдачей (`validate_dataset.py`)

- Датасет перед архивацией и сдачей **в обязательном порядке** прогоняется официальным скриптом-валидатором организаторов.
- Результат работы валидатора (лог/отчёт) должен завершаться со статусом `VALID` / `PASS` без критических предупреждений и прикладываться к сдаваемым материалам.
